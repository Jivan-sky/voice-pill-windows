# Voice-Pill 中立接口契约

> 对应 issue [#5](https://github.com/Jivan-sky/voice-pill-windows/issues/5)。
> 解决的问题：插件 = **宿主机制 + 接口**。宿主机制每家都不一样（Codex 是 MCP + 三个钩子，
> Claude Code 是 hooks + 技能），**接口只有一个**。接口不定死，接第二家就等于把桥再写一遍。
>
> 本文只写**语义**。管道名怎么算、authkey 怎么握手、超时几秒、JSON 之外怎么编码——
> 这些是传输层，**不进契约**。换掉命名管道换成别的，本文一个字都不用改。

## 0 契约覆盖哪几个动词

| 动词 | 在契约里 | 为什么 |
|---|---|---|
| `take` | ✅ | 宿主每轮对话前把攒下的话取走 |
| `speak` | ✅ | 宿主让本机出声 |
| `capture` | ✅ | 宿主把一段文本交给一个落点（issue #1 / #4） |
| `shutup` | ✅（附在 `speak` 一节） | 它是 `speak` 的逆操作，拆开写两份必然走散 |
| `status` / `start` / `stop` / `cancel` | ❌ | 本机运维动词，宿主不接。它们改的是引擎自己的状态，不是「谁在用这个能力」 |

**现状**（`src/bridge.py:98`）：`COMMANDS` 现在是
`("status", "start", "stop", "cancel", "take", "speak", "shutup", "capture")` —— 八个都在表里了。
**在表里 ≠ 已验收**：§5 那几条端到端用例还没跑过。

## 1 `take` —— 取走攒下的话

**语义一句话**：把本机攒下的待投喂文字**取走并消费**。同一批文字只可能被一个宿主拿到一次。

| | |
|---|---|
| 请求参数 | 无 |
| 响应 | `{"texts": [str, ...], "count": int, "seq": int}` |
| 顺序 | 旧 → 新 |
| 空队列 | `{"texts": [], "count": 0, "seq": <不变>}` —— **不是错误** |

**规则**

1. **取走即消费**：调用返回后，这批文字在引擎侧不复存在。这条是硬语义，不是实现细节——
   两个宿主（Codex 与 Claude Code）同时挂着时，靠它保证不重复投喂。
2. **保鲜期**：`settings.pending_ttl_minutes`，`0` = 不过期。过期的那批**既不返回、也不再留在队列里**。
   依据：队列里的字只在下一次往宿主发消息时才被取走；没有时效的话，几天前随口说的一句会在几天后
   被塞进一轮对话，和当时真正的意图搅在一起（`src/main.py:654` 的注释原文）。
3. **不接参数**：现在传什么都不生效。契约层面明确写死，免得将来有人以为 `take` 能按消费者过滤——
   按消费者过滤会把「取走即消费」拆掉。
4. **`seq`：累计**已投递**条数，只增不减。** 递增的是**条数**而不是调用次数——只有按条数跳号，
   宿主才能把「被另一个宿主取走了 N 条」和「就是没话」分开。过期的那些**不占号**：它们谁也没
   送到，算进去会把丢弃误报成一次投递。

   **宿主怎么用它**：自己记一个 `last_seq`，每次拿到 `(count, seq)` 后算

   ```
   missed = seq - count - last_seq        # 首次调用把 last_seq 置为 seq，不比较
   ```

   `missed > 0` 就是在这两次调用之间被别的宿主取走了 `missed` 条。算完把 `last_seq` 更新成 `seq`。

   **唯一的例外是引擎重启**：`seq` 和待取队列一样只在内存里（队列本就一退即空，没有哪条
   「被取走过」需要跨重启记账）。重启后序号归零，宿主会看到 `seq < last_seq`——
   那是重启，不是回退，按「重新开始记账」处理，别当成负数条错过。

**坏输入**

| 情形 | 行为 |
|---|---|
| 引擎不在 | 调用方拿到「连不上控制面」，**不是**空结果。两者必须能分开：空结果 = 引擎在、只是没话；报错 = 引擎不在，这一轮别指望有话 |
| 传了参数 | 忽略 |

## 2 `speak` —— 让**本机**出声

**语义一句话**：声音从**引擎所在的那台机器**出。不是让对端出声——「对端出声」在跨机场景下是另一个问题，本契约不管。

| | |
|---|---|
| 请求参数 | `text`（str，可空）、`auto`（bool，可选） |
| 响应 | `{"spoken": str, "chars": int, "skipped"?: str}` |

`skipped` **只在被挡时出现**（现在的实现就是不带这个键，不是给 null）。
契约层面把两者定死为同一件事：**调用方不许靠「键在不在一」分支**——`skipped` 缺失与
`skipped: null` 都读成「没被挡」。多一个键少一个键不该改变调用方的一轮对话。

**规则**

1. **`spoken` 是实际会念的文本，可能与入参不同**，调用方必须按返回值记账、不许按入参记账。
   两处会改：① markdown 被剥掉；② 截断到 `settings.speak_max_chars`。
   连入参一起回的原因就是这个——插件得能如实说「我念了哪些」，而不是自己以为念了全部
   （`src/speak.py:164` 的注释原文）。
2. **`auto` 的两种身份**：
   - `auto=true` = 「每轮回复自动念」（Stop 钩子那条路），**受 `settings.speak_replies` 管**；
   - `auto=false` / 不传 = 明确要求念（宿主的 `speak` 工具），**不受开关限制**。
   判断只在引擎这一处做。依据：让钩子和常驻进程各判一遍，两份规则必然走散（`src/main.py:622`）。
3. **被开关挡住不是错误**：返回 `{"spoken": "", "chars": 0, "skipped": "speak_replies=false"}`。
4. **空文本不出声**：返回 `{"spoken": "", "chars": 0}`，`skipped` 为 null。
5. **非阻塞**：`speak` 立刻返回，只负责入队与启动发声线程。调用方不等待念完。

**`shutup`**：请求参数无，响应 `{"speaking": false}`。
语义是**清空待播队列 + 立刻断流**，不只是「停当前这一句」——用户改主意时，排队等着的那几句也不该再念。

**坏输入**：**假值**（缺省 / `""` / `null`）→ 不出声，返回 `{"spoken": "", "chars": 0}`，不报错。
理由：念不出声是可见的（安静），报错反而会打断宿主的一轮回复。

> 现状提醒：实现是 `str(args.get("text") or "")`（`src/main.py:625`），所以**非字符串的真值会被
> `str()` 之后照念**（比如传了个对象，会把它的 repr 念出来）。契约不要求为此加一道类型门禁——
> 但那意味着「传错类型」不会报错、只会念出怪东西，宿主侧别拿它当输入校验用。

## 3 `capture` —— 一段文本，落到一个确定的落点

**语义一句话**：给定一段文本，落进**一个**落点，并且**同一次投递只落一篇**。

| | |
|---|---|
| 请求参数 | `text`（str）、`text_id`（str） |
| 响应 | `{"accepted": bool, "dest": str, "reason": str, "path": str, "text_id": str, "duplicate": bool, "skipped": str 或 null}` |

**规则**

1. **落点由 `route()` 决定，不由调用方决定。** 调用方只给文本。
   为什么不让调用方指定落点：`route()` 是纯函数（同文本 → 同落点 + 同理由，可重放），
   把落点决策放在调用方等于把这个性质分散到每个宿主里，接第二家就得再证一遍。
   口令（显式）定落点、关键词只出**建议**、建议不生效——判据见 `src/capture.py` 的 `route()`。
2. **`reason` 跟着落点一起回**，并由落点侧写进笔记的 frontmatter。
   `route:` 与 `reason:` 里出现的落点一律是**目录名**（`04_Projects`），不是机器路径。
3. **`text_id` 是幂等键，由调用方提供。**
   - 同一个 `text_id` 重复投递 → `duplicate: true`，**不写第二篇**，`path` 指向第一次那一篇。
   - 依据：跨机那条路（issue #4）要经 SSH 中继，ack 丢失后重试是**常规情况**。
     而落盘文件名由时间生成（`src/capture.py:140` 的 `stem`），**跨秒重试会生成第二个不同 stem**，
     连「退序号」都不会发生，两篇平级重复——所以幂等不能靠文件名，必须靠 `text_id`。
   - 去重**必须先于第一次写盘**，且索引**必须落盘**（不能只存内存：`_pending` 那种 deque
     进程一退就没了，而引擎会被看门狗重启）。
4. **`text_id` 缺失 → 报错，不落盘。**
   为什么是报错而不是「按内容哈希兜底」：同一个人今天把同一句话口述两遍是**合法**的，
   内容哈希会把第二遍当成重复吃掉。宁可吵，不许猜。
5. **写者是单数，但算落点的不是那个写者。** 一次投递只有一侧落盘；跨机场景下权威副本在宿主，
   引擎把文本**连同算好的 `dest` / `reason`** 一起送过去，宿主只落盘、**不重算落点**。
   为什么不能「引擎只送文本、宿主自己算」：那等于把 `route()` 复制到每一个落盘方，
   规则 1 想避免的「接第二家就得再证一遍」就原样回来了。
6. **跨机时文本会等，而且是逐条等的。** 落盘方不可达时文本进 spool 等下一轮；等待期间按 `pending_ttl_minutes` 过期，
   基准是**每一条各自的入队时刻 → 它自己的落盘时刻**，不是投递时刻——按投递时刻算永远不过期，等于没有这条。
   为什么非写「逐条」不可：多条目一起 flush 时，「入队 → 落盘」最容易被读成**一个全局 cutoff 一刀切**。
   `take` 的保鲜期不是那么算的（`src/main.py:668-669` 拿每条自己的 `stamp` 比 cutoff，cutoff 只是阈值），
   两条路同一个语义，别在这里走散。
   同样一个 `pending_ttl_minutes`：`take` 那边的现值是 30 分钟（`src/config.py:32`）。
   理由与 `take` 的保鲜期同源：几天前随口说的一句不该在几天后落地，还假装自己是刚说的。
   本机直落没有队列，这一条不生效，它只在跨机那条路上咬人。

7. **过期是回执，不是静默丢弃。** 一条文本过期被丢掉时，`accepted: false` + `skipped` 必须回到**投递方**
   ——即调 `capture` 的那一侧，跨机场景下就是算出 `dest` / `reason` 的那台。**回执归谁必须写明**，
   否则跨机那条路上就是无声消失。
   为什么不照抄 `take` 的静默过期：`take` 丢的是「这一轮的投喂」，而用户本来就没指定什么时候听；
   `capture` 丢的是用户明确要落库的内容，静默丢**就是数据丢失**，而且事后无从发现。
   这一条只定「回执归谁」，不定怎么送：投递方可以等落盘回执，也可以在后续轮次把过期的那些补报出来。

**坏输入**

| 情形 | 行为 |
|---|---|
| 引擎不在 | 调用方拿到「连不上控制面」，文本**不丢**——重投是安全的，因为 `text_id` 幂等 |
| `text` 为空 | `accepted: false` + `skipped`，不落盘。空捕获不该在知识库里留一篇空笔记 |
| `text_id` 缺失 / 空 | 报错（见上） |
| 保鲜期已过 | `accepted: false` + `skipped`，**且回执必须回到投递方**（见规则 7）。**基准**：逐条各自的 spool 入队时刻 → 它自己的实际落盘时刻，窗口同一个 `pending_ttl_minutes`（0 = 不过期）。本机直落没有队列，这条不生效 |

## 4 双宿主：两个插件，一份能力

**判据（issue #5 原文）**：同一份 `voicepill.exe` 同时服务两个宿主且**互不干扰**——
待取文字只有一份，取走即消费，不重复投喂。

这条**只靠 `take` 的规则 1 成立**，不需要在引擎里加「谁是 Codex、谁是 Claude Code」的概念。
哪个宿主先问，字就归谁——同一次说话本来也不该被两家各投喂一遍。

`speak` 同理：两个宿主都调同一个动词，出声的永远是同一台机器的同一支扬声器。

**Claude Code 接线放本仓库 `plugins/claude-code/`**：skill + hook + MCP 注册 + **一份新的安装脚本**
（不是几行配置——`plugins/install.py` 现在只认 Codex：`~/plugins/voice-pill`、
`~/.agents/plugins/marketplace.json`、`codex plugin add`，三处都是 Codex 专有）。

**契约文档放本仓库 `docs/`（就是本文）**：它是 exe 与宿主之间的契约，跟着代码走、跟着代码版本走。
知识库只留一个指针，不存副本——存副本就会有两份会走散的规则。

### 4.1 待拍板：后到的宿主「静默拿空」

两个宿主**每轮都调 `take`**（Codex 的 `UserPromptSubmit` 钩子与 Claude Code 的同类钩子），
所以这不是「同时在线才抢」——先问的那个把字全吃掉，后到的那个拿到 `{"texts": [], "count": 0}`，
而**空结果与「本来就没话」长得一模一样**，事后从日志里分不出来。

这不需要新机制就已经成立，所以它当初是待拍板项、不是本节的边角料。三条路（保留作为选择记录）：

| 路 | 做法 | 代价 |
|---|---|---|
| (a) 保持现状 | 哪个先问归谁，后到的静默拿空 | 事后查不出「我错过了一条」 |
| (b) 回执 | `take` 额外回「这批被谁取走了」 | **要在引擎里引入宿主身份**——正是本节上面刚拒绝的东西 |
| (c) `seq` 单调计数 | `take` 多回一个只增不减的序号，**按条数递增**（不是按调用次数）；宿主发现自己跳号就知道被取走过 | 知道「被取走过」、不知道被谁；多一个字段 |

(c) 是我给 Codex 的建议：它买到 (b) 的可诊断性，但不引入宿主身份。
**按条数递增是写死的**：只有按条数跳号才能报出「你错过了 N 条」；按调用次数跳号只知道「发生过」。

**已拍板：走 (c)。** 落法见 §1 规则 4（响应形状、宿主算法、重启例外都在那一处，
本节不重复）。本节由此冻结。

## 5 怎么算验收过

每条命令要有**可重放用例**，正例与坏输入都要有：

| 动词 | 正例 | 坏输入 |
|---|---|---|
| `take` | 攒 3 条 → 取走 → 再取为空 | 引擎不在（报错 ≠ 空结果）；保鲜期已过的不返回 |
| `speak` | 普通文本 / 带 markdown / 超长截断 | 空文本；`auto=true` 且 `speak_replies=false` |
| `capture` | 落一篇、`reason` 说得清为什么落这 | 空文本；缺 `text_id`；同 `text_id` 重投 |

端到端两条（issue #5 原文）：

1. **只改宿主侧配置**，Claude Code 就能「说一句 → 文字进本轮上下文」；
2. 同一份 `voicepill.exe` 同时服务两个宿主，**不重复投喂**。
