# 规格：口述落库（Voice Pill → Obsidian Inbox）

- 日期：2026-10-03
- 关联：https://github.com/Jivan-sky/voice-pill-windows/issues/1（第一步：先落库）
- 状态：待实现

## 1. 问题

按 Fn 说完一句话，文字粘到光标就结束了：它进了对话，但不进组织资产。想留下来，只能再说一遍或者手动复制进 Obsidian。

## 2. 目标

口述产生的内容，能用一个明确动作落进知识库的捕获区，之后按既有流程归档。
落点选定 `00_Inbox/`——库自己的约定就是「先扔进来，别分类」。

**不在本次范围**：自动分类到 `03_Knowledge/` 等最终目录（那是 `/process-inbox`、`save-*` 技能的事）；L1 插件化（issue 的第 2 步）。

## 3. 契约增量（先做，否则落库会弄脏校验）

`00_Inbox/` 在知识库契约里原有缺口：词表没有对应它的 `type` 值，而 `_资产契约.md` 的不变量要求每篇 md 恰好 1 个 `type/`。实测现状：全库 md（扣 `_scripts/`）197 篇，带 `type/` 的 196 篇，唯一缺口是 `03_Knowledge/03-接口_数据/ANC.md`（无 frontmatter）。若再丢进无 type 的文件，缺口就从 1 变 2。

1. `_词表.md` §1 type 表新增一行 `type/inbox` ↔ `00_Inbox/`，并同步篇数与合计。
2. `_资产契约.md` 给 `00_Inbox/` 定性：未定级捕获区；性质＝待分类原始捕获；保留＝每周清空；移动＝移出即归位到 L1/L2。

## 4. 触发（可换插槽）

默认：转写文本以口令开头才落库。默认口令 `记一下`，可配多个。
判定是一个纯函数，因此换成别的触发方式（例如双击 Fn）只改热键层，落库逻辑一行不改。

未命中口令时，行为与今天完全一致。

## 5. 行为

命中时：

- 剥掉口令，其余正文写入 `00_Inbox\YYYY-MM-DD-HHMMSS.md`
- 用 `O_CREAT|O_EXCL` 创建；同秒撞名退到 `-2`，绝不覆盖已有文件
- frontmatter：`title` / `created` / `tags: [type/inbox]`
- 悬浮条回执「已落 Inbox」
- **不粘贴**——避免把「记一下xxx」连口令一起塞进当前对话
- **正文**仍进待取队列，控制面 `take` 仍取得到 —— 队列里放的是剥掉口令的正文，
  不是原话：队列正是被 `UserPromptSubmit` 钩子注入进对话的，上面那条「不粘贴」的
  理由对它一样成立（Jivan 2026-10-05 拍板）

写失败时不丢字：悬浮条报失败，文字仍在剪贴板与待取队列（同样是正文，不含口令）。

## 6. 配置

`settings.json` 新增三个字段，默认关闭：

- `capture_enabled: bool = false`
- `capture_dir: str = ""`（留空＝未配置）
- `capture_prefixes: list = ["记一下"]`

仓库里不写任何机器路径。

## 7. 验收

- 说「记一下：明天跟 A 确认接口」→ 光标处不出现文字；`00_Inbox` 下出现新文件，内容为那句话加 frontmatter
- 说「帮我把这行改成异步」→ 照旧粘贴，Inbox 无新文件
- `capture_enabled=false` → 行为与今天一致
- `tools\capture-selftest.py` 全绿
