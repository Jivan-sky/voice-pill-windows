# 规格：插件钩子与 MCP 服务端换成 Go 单 exe

- 日期：2026-10-03
- 关联：https://github.com/Jivan-sky/voice-pill-windows/issues/2
- 状态：待实现

**技术选型（一行）：** Go 1.27.0 —— 三个钩子「每次提交 / 每轮 / 每会话」都被拉起、MCP 服务端每会话拉起，判据 1 命中；要单文件分发、跨平台，判据 2、3 命中。本机已装，`go get github.com/modelcontextprotocol/go-sdk@v1.8.0` 实测成功；但它的间接依赖在本机走默认代理会撞 IPv6 卡死（实测），构建脚本里固定 `https://goproxy.cn,direct`，详见计划「注意事项」。代价：重写 8 个工具与 3 个钩子入口，`install.py` 删掉 venv 与 pip 分支；产物是一个约 12 MB 的 exe（实测）。

## 1. 问题

两件事，一件是慢，一件是错。

**慢**：会话里每一轮回车（`UserPromptSubmit`）、每一轮结束（`Stop`）、每次开新会话（`SessionStart`）都要拉起一个 Python 解释器；为此还得维护一份只装了 `mcp` 的独立 venv（`%LOCALAPPDATA%\VoicePill\plugin-venv`），安装脚本要建 venv、跑 pip。这三条路都在用户能直接感觉到的关键路径上。

**错**：控制面是给**外部进程**用的契约，`src\bridge.py` 顶部写的是「一行 JSON 对象」；实际线格式却是 `multiprocessing.connection` 的 HMAC-MD5 挑战应答加 pickle 帧——**今天这条通道只有 Python 能说**。这与 issue #1 的「让 Codex 之外的 Agent 也能挂上」直接冲突：契约是语言无关的，实现却把语言钉死了。

## 2. 目标

1. 插件侧交付物只剩一个 exe：不带子命令时是 MCP stdio 服务端（8 个工具），带子命令时是三个钩子入口。
2. 控制面**新增**一条语言无关的 NDJSON 通道：同样的七个命令、同一份密钥、同样的管道名派生规则，另取一个前缀。原来的 `multiprocessing` 通道**一个字不改**。
3. 仓库工作区里不再出现任何本机绝对路径。

**不在本次范围**：引擎本体（采音、ASR、TTS、热键、看门狗、锚点）仍是 Python，一行不改。插件对外行为不变——工具名、参数名、返回字段、三个钩子的触发事件与超时都不许动。

## 3. 现状（Go 侧要逐条对齐的事实）

### 3.1 控制面（`src\bridge.py`）

- 管道名 `\\.\pipe\VoicePill-` + `sha256(normcase(app_dir()))[:16]`；`app_dir()` 就是 `%LOCALAPPDATA%\VoicePill`。
- 密钥 `%LOCALAPPDATA%\VoicePill\bridge.key`：文件里是 64 个 hex 字符 = 32 字节。
- 一次连接只处理一条请求。请求 `{"cmd": ..., "args": {...}}`；响应 `{"ok": true, "data": {...}}` 或 `{"ok": false, "error": "人话"}`。
- 七个命令：`status` / `start` / `stop` / `cancel` / `take` / `speak` / `shutup`。
  - `status` 返回 `pid` / `phase` / `provider` / `provider_label` / `hotkey` / `hotkey_alive` / `hud` / `pending` / `speaking` / `tts_loaded` / `uptime_seconds`。
  - `take` 是**取走并清空**语义，只返回保鲜期（`pending_ttl_minutes`，默认 30 分钟）内的字，返回 `{"texts": [...], "count": n}`。
  - `speak` 读 `args.text` 与 `args.auto`：`auto=true` 受 `settings.speak_replies` 管（Stop 钩子那条路），`auto=false` 不受开关限制（插件工具那条路）。
  - `phase` 只有三个值：`idle` / `recording` / `transcribing`。
- 客户端建连超时 3.0 秒、单条请求上限 64 KiB、连接空闲上限 60 秒。
- 服务端对握手失败**不致命**：`AuthenticationError` 被 `continue` 掉，下一个正常客户端照样能连（这是踩出来的，见移植方案 12.5）。

### 3.2 八个 MCP 工具（`plugins\voice-pill\mcp_server.py`）

工具名与行为：`voice_pill_status` / `voice_pill_listen` / `voice_pill_stop` / `voice_pill_cancel` / `voice_pill_take` / `voice_pill_speak` / `voice_pill_shutup` / `voice_pill_prompt_hook`。

- `listen(seconds=10.0)`：先 `_ensure_engine()`（连不上就拉起看门狗，最多等 20 秒）→ `start` → 每 `POLL_INTERVAL=0.3 s` 轮询 `status`，直到 `phase == "idle"`（用户自己按 Fn 松手也会提前结束）或超过 `seconds` → `stop` → `_wait_for_result()`（轮询到 `idle` 后 `take`，最长 `TRANSCRIBE_TIMEOUT=60 s`；引擎 local 后端收尾超时是 30 秒，留一倍余量）。
- `stop`：不在录音就直接取队列里的字，在录就 `stop` 再等结果。
- `take`：取走并清空。
- `speak(text)`：空文本报错，且传 `auto=False`。
- `prompt_hook`：任何异常都返回 `{"continue": true}`；有待取文字时返回 `hookSpecificOutput.additionalContext`，正文是「用户刚刚用语音输入（Voice Pill）说了以下内容，请把它当作本轮意图的一部分：\n」加逐条换行拼接。

### 3.3 三个钩子

入口是三个 `.cmd`，`hooks.json` 里的超时分别是：`SessionStart` 20 秒、`UserPromptSubmit` 10 秒、`Stop` 5 秒。

- 共同契约：stdin 读 JSON（读不到当空对象）；stdout **任何情况下都要打一行 JSON**（`{"continue": true}`）；任何异常都吞掉，只写日志。理由写在各自 docstring：绝不拦住用户这一轮。
- `UserPromptSubmit`（`take`，5 秒超时）：有待取文字才注入 `additionalContext`。
- `Stop`（`speak`，5 秒超时）：取 `last_assistant_message`，`text[:4000]` 先截一道，传 `auto=true`。
- `SessionStart`：见下节，是唯一有非平凡行为的一个。

### 3.4 `SessionStart` 的非平凡行为（Go 必须复刻）

1. 沿父链走到**最外层**的 Codex 进程（认 `codex.exe` / `chatgpt.exe`，`MAX_HOPS=16`，用 `NtQueryInformationProcess(ProcessBasicInformation).InheritedFromUniqueProcessId` 取父 PID）。
2. 把 `(pid, image)` 写进 `%LOCALAPPDATA%\VoicePill\anchor.json`，内容是 `{"pid": .., "image": .., "at": <Unix 秒浮点>}`；内容没变就不动文件（免得白刷 mtime）。找不到锚点也照常往下走，绝不因为绑不上就不干活。
3. 确保看门狗在跑：互斥体名 `Local\VoicePill.Windows.Supervisor`，已有人在守就什么都不做（所以要幂等，开机自启拉起来的那个不能被重复拉起）。
4. 拉起方式：`DETACHED_PROCESS|CREATE_NO_WINDOW` 起 `<仓库根>\.venv\Scripts\pythonw.exe src\supervise.py`，cwd 是仓库根。
5. 拉起后**最多等 6 秒**、每 0.3 秒探一次 `status`——「开了 Codex 立刻按 Fn」是最容易失败的一刻。已经在跑就立刻返回，不拿这几秒去拖慢每一次开新会话。「看门狗不在了就收手」必须等**先见过它活着**才算数（刚 spawn 出来那一瞬它还没拿到互斥体，实测踩过）。

### 3.5 一个顺带的补丁（Go 侧天然不再需要）

`hook_*.py` 与 `mcp_server.py` 都调 `console.make_output_safe()`：管道下 Python 的 stdout 会退回 GBK，而 Codex 按 UTF-8 读，中文提示语会被编成乱码塞进模型上下文（静默生效，比崩掉更难发现）。Go 直接写字节，没有这层编码转换——**这一条不是「要复刻」，是要在计划里写明「已验证不再需要」**。

## 4. 决策：控制面加一条与语言无关的通道（Go 不碰 pickle）

- 办法：在 `src\bridge.py` 里**新增**一条 NDJSON 命名管道，同七个命令、同一份 `bridge.key` 做挑战应答，管道名另取一个前缀。原 `multiprocessing` 通道保留不动——现有 Python 插件与 `tools\bridge-selftest.py` 全部继续可用，这是纯增量。
- 备选（**不采用**）：让 Go 去复刻 `multiprocessing.connection` 的 HMAC-MD5 握手与 pickle 帧（约 300 行，还要配一份金标准对拍测试）。不采用的理由：那等于把一份 Python 私有线格式**永久固化**，而 `bridge.py` 自己写的契约本来就是「一行 JSON」；契约说一套、实现做另一套，才是这次的病根。

线协议见第 6 节——它是本次唯一的跨语言接口，必须写得能照着实现。

## 5. 仓库洁净：绝对路径不再进工作区

`install.py::render_files` 现在把本机绝对路径写进了**仓库工作区**：`plugins\voice-pill\.mcp.json` 与 `plugins\voice-pill\hooks\hooks.json` 里就是两份形如 `C:\Users\<用户名>\...` 的机器路径，而这两个文件是 git 跟踪的。这违反本仓库「项目文件只留能力与用法，不写本机绝对路径」的规矩。

顺手改掉。两种做法：

- **(A) 模板 + 安装时渲染（推荐）**：仓库里提交 `.mcp.json.template` 与 `hooks.json.template`（占位符如 `<PLUGIN_DIR>` / `<EXE>`），`install.py` 渲染出真正的 `.mcp.json` / `hooks.json`，并把这两个渲染产物加进 `.gitignore`、同时在 `install.py` 里校验它们确实被忽略（误提交就报错退出）。模板本身没有任何机器路径，仓库里任何一处都查不到 `C:\Users\<用户名>` 这类机器路径。
- **(B) exe 自己解析自己的位置，连渲染都不需要**：把「引擎在哪」交给 exe 自己算（解析 junction），`install.py` 不再渲染引擎路径。**但 `command` 必须是绝对路径**（实测相对路径报 os error 3），所以 exe 自己被调用的那条路径仍然要渲染——(B) 只能省掉一半，省不掉的那一半恰恰还是机器路径。因此不采用 (B) 作为主线，只把「自解析」用在**引擎根**上（exe 不必被喂仓库路径）。

(A) 的渲染产物落在插件目录里（那就是仓库工作区，因为 `%USERPROFILE%\plugins\voice-pill` 是指向仓库的目录联接），所以严格说不是「渲染到 Codex 侧」：Codex 自己的那份副本在 `%USERPROFILE%\.codex\plugins\cache\personal\voice-pill\<版本>\`，是 `codex plugin add` 时整包拷的，安装脚本不该去改它（一次版本变化或清缓存就悄悄失效）。渲染产物是**构建产物**、不是项目文件，所以用 `.gitignore` 挡住即可，(A) 与「项目文件只留能力与用法」并不冲突。

## 6. 线协议（NDJSON 通道契约）

管道名：`\\.\pipe\VoicePill-Json-` + `sha256(normcase(app_dir()))[:16]`（同一个 tag，换前缀）。自测可用环境变量覆盖（`VOICEPILL_JSON_PIPE_NAME`），不碰真身。

一次连接一条请求，编码 UTF-8，JSON 紧凑单行，`\n` 分帧：

```
服务端 -> 客户端   {"nonce": "<32 位小写 hex>"}                 # 16 字节随机数
客户端 -> 服务端   {"auth": "<64 位小写 hex>"}                   # HMAC-SHA256(key, ASCII(nonce))
服务端 -> 客户端   （鉴权失败：{"ok": false, "error": "..."} 后关闭）
客户端 -> 服务端   {"cmd": "status", "args": {}}
服务端 -> 客户端   {"ok": true, "data": {...}}  |  {"ok": false, "error": "人话"}
```

- 密钥同一份：`%LOCALAPPDATA%\VoicePill\bridge.key`（64 hex = 32 字节）。
- 上限与超时沿用旧通道：整条连接（握手 + 一次请求）建连超时 3 秒、单行上限 64 KiB、空闲上限 60 秒。
- 服务端对坏客户端**不致命**：鉴权失败、超长行、非 JSON、未知命令都只回一条 `ok:false` 并关掉这条连接，accept 循环不受影响。
- 未知字段忽略；命令集合与参数名和旧通道逐字一致（第 3.1 节）。

## 7. 四个阶段

每个阶段都能独立验证、独立回滚。

1. **引擎侧通道**（`src\bridge.py` + 新自测）：加 NDJSON 服务端与客户端，七个命令打通；旧通道与 `tools\bridge-selftest.py` 必须仍然全绿。
2. **Go 侧**（一个 exe）：先做 spike——最小程序把 `status` 往返打通，证明通道与鉴权没问题；再铺 8 个工具与 3 个钩子入口。
3. **安装与接线**：`install.py` 删 venv/pip 分支、改为放置并校验 exe；`hooks.json` / `.mcp.json` 改指 exe；仓库里的绝对路径改成模板。
4. **真 Codex 验收**：8 个工具、三个钩子各验一次；与 Python 版做冷启动对比写进 README；通过后再删旧的 Python 插件文件。

## 8. 验收

- 旧通道不回归：`tools\bridge-selftest.py` 全绿；`tools\bridge-json-selftest.py` 全绿。
- 8 个工具逐个在真 Codex 里调一次，返回字段与 Python 版一致；`voice_pill_listen` 能拿到真话。
- 三个钩子各验一次：`UserPromptSubmit` 能把口述注入当轮；`Stop` 能出声；`SessionStart` 能拉起引擎，且第二次运行幂等（不重复拉起）。
- 仓库里 `git grep` 不到任何本机绝对路径（模板除外，模板里是占位符）。
- README 里记下冷启动对比（Python 版 vs Go 版，同一个测试方法、同一台机器）。

## 9. 顺着做但不混进来的

- Go 侧如果发现 `NtQueryInformationProcess` 之外更稳的取父进程办法（例如 Toolhelp32），可以在计划里当作实现选择，但**必须与 Python 版 `anchor.find_anchor()` 对拍**（同一进程树里跑两边，pid 与 image 一致）才改用。
- `%USERPROFILE%\plugins\voice-pill` 这条目录联接的由来（路径里的 `&` 会把 cmd 拆断）见移植方案第 13 节，本次不重新论证。
